> 2026-07-21 更新：將 `HANDOFF.md` 與 chezmoi session checkpoint 納入 Codex、Claude、AntiGravity 共用的開工／收工生命週期；本文件仍是自含式 Skill 安裝文件。


## 目標

把「開始新專案」變成固定工作模式，不只套用在單一專案。

## 前置條件

- 已完成 `README.md` 的設定表。
- 已決定 `{{WORK_ROOT}}`。
- 若使用 Obsidian，已完成 `04-建立第二大腦-Obsidian`。
- 若使用 GitHub，已完成 `03-連接-GitHub`。

- 新電腦若要立即執行三 Agent 任務，依 Item 16 的「Agent CLI 按需安裝」逐機安裝並驗證 Claude Code 與 Gemini CLI；登入憑證只留在各機器本機，不由 chezmoi、Google Drive、LazyPack 或專案 repo 同步。

## 新專案標準流程

1. 先檢查 `{{WORK_ROOT}}` 與是否已有同名資料夾。
2. 問清楚：
   - 專案名稱
   - 用途
   - 工作資料夾
   - Agent profile：固定為 Codex＋Claude＋AntiGravity；另記錄 connector、MCP、sandbox、模型或腳本的原生 adapter 差異
   - GitHub repo 是否需要
   - public / private
   - GitHub Pages 是否需要
   - Obsidian 駕駛艙路徑
   - Firebase 是否需要
   - Netlify 是否需要
   - 部署目標
3. 建立工作資料夾：

```text
{{WORK_ROOT}}/<project-name>
```

4. 建立或補齊：
   - `AGENTS.md`
   - `CLAUDE.md`（固定建立；內容只為 `@AGENTS.md`）
   - `HANDOFF.md`（共用 Agent profile）
   - `README.md`
   - `.gitignore`
   - Git repo
5. 建立 Obsidian 駕駛艙：

```text
{{OBSIDIAN_PROJECTS}}/<project-name>/專案工作流程.md
```

6. 若使用個人助手資料層，建立專案本地：

```text
100_Todo/
  drafts/
  projects/
  archive/
200_Reference/
  writing-samples/
  templates/
  past-work/
  docs/       # 部署素材、靜態頁面與可公開文件；需要時建立
  scripts/    # 專案腳本與可版本化 runtime 資料（例如 requirements.txt）；需要時建立
    runtime/  # 腳本執行期的中間檔與快取；需要時建立
```

**虛擬環境不在專案資料結構內。** Python／工具 venv 一律建在本機
`~/.local/share/agent-tools/project-runtimes/<專案名>/.venv`，用共用腳本建立：

```bash
"{{SYNC_ROOT}}/skills/cross-device-sync/scripts/project-venv.sh" ensure --project-root .
```

原因：venv 綁定絕對直譯器路徑、內含上千個小檔。專案資料夾預設放在 Google Drive，
同步服務會把冷檔內容逐出成 placeholder，下次 import 得逐檔重新下載——實測單一 import
可達 144 秒，整個 venv 甚至逾時。repo 裡只留 `requirements.txt`。

只有需要專案本地 assistant skill 或專案獨立記憶時，才建立：

```text
000_Agent/skills/
000_Agent/memories/
```

`000_Agent/skills` 只放該專案自己的 assistant skill、流程草稿或局部工具說明；不要 symlink 到全域 skills。需要全域觸發的 skill 才安裝到 `{{SYNC_ROOT}}/skills`，再由 Item 16 的 chezmoi 原生入口讓 Codex、Claude、AntiGravity 讀取。
`000_Agent/memories` 只在專案真的需要獨立助手記憶時才建立。

若專案文件需要記錄 Arry 助手 / 個人助手 Obsidian 同步範圍，固定寫成：`knowledge/` 同步時排除頂層 `visual-note-references/` 與 `.DS_Store`；`memories/` 只同步根目錄第一層檔案，不同步 `extensions/`、`rollout_summaries/`、`skills/` 或其他 memories 子資料夾；統一執行 `arry-assistant/scripts/sync_obsidian_mirror.py`。圖解作品只保留全域 Knowledge 與 Obsidian 創作庫兩處。

若初始化過程需要新建或修改 skill，必須先使用 `codex-skill-creator`：

- 跨專案可重用：`{{SYNC_ROOT}}/skills/<skill-name>`，並同步 LazyPack 與 Obsidian 全域 Skills 索引。
- 只服務單一專案：`<project-root>/000_Agent/skills/<skill-name>`，並記錄到專案駕駛艙。
- 不建立其他全域或專案 skill root。

7. 若需 GitHub，再建立 repo 與 remote。
8. 若需 Firebase，再建立或連接 project。
9. 若需 Netlify，先確認 Netlify CLI/MCP 可用、team、site name 或 site ID、output folder、production/preview 意圖，再建立或連結 site。

## 專案入口

- `CLAUDE.md`：固定只含 `@AGENTS.md`，不複製規則。

## 開工

- 讀本檔。
- 一律讀取 `HANDOFF.md` 並與 live Git／檔案狀態核對；若缺少，記錄由本次收工補建。
- 執行 `{{SYNC_ROOT}}/skills/cross-device-sync/scripts/session-sync-checkpoint.sh --phase startup --sync-root "{{SYNC_ROOT}}" --update`。
- checkpoint 會自動執行 bootstrap dry-run 與 `chezmoi status`；只在 chezmoi source 已有 commit、remote 且 worktree 乾淨時，先備份再執行 `chezmoi update`。條件不足時安全跳過並回報理由。
- 讀 Obsidian 駕駛艙。
- 檢查 Git 狀態。
- 除上述受控 chezmoi update 外，不自動對專案 pull、commit、push 或 deploy。

## 收工

- 一律建立或更新 `HANDOFF.md` 的 current state、next action、blockers、last verified。
- 執行 `{{SYNC_ROOT}}/skills/cross-device-sync/scripts/session-sync-checkpoint.sh --phase shutdown --sync-root "{{SYNC_ROOT}}"`，確認 bootstrap dry-run 與 `chezmoi status`。

- 回報 Git 狀態。
- 只有使用者要求時才 commit / push。

- 不提交 `.env`、API key、token、密碼、Admin 憑證、個資或敏感資料。

## 踩坑修正

- 新增全域 skills 後，要重開 Codex 對話或重啟 App。
- Item 10 管理「專案生命週期與交接」，Item 16 管理「電腦與 Agent 全域入口」；不要把 chezmoi templates 放進每個專案。
- `HANDOFF.md` 不是第二份 Obsidian 駕駛艙，也不是 durable memory。只留能讓下一個 Agent 安全接手的最小現況。
- 不要在每次收工對既有 chezmoi templates 重跑 `chezmoi add`；這會移除 template 屬性，並可能把機器實體路徑寫回 source。只有新增 Item 16 白名單入口時，才使用受控的 `chezmoi add`。
- Claude 的 `CLAUDE.md` 若複製完整 `AGENTS.md`，兩份內容很快會漂移；固定使用 `@AGENTS.md` 薄 adapter。
- 來源文件若提到 來源工具規則檔 或 來源工具的 skills 路徑，要先判斷層級：全域觸發才轉成 `{{CODEX_HOME}}/skills`；專案/助手本地 skill 轉成 `000_Agent/skills`。
- Codex 側邊欄不會即時跟著 Finder / 雲端硬碟改名刷新。
- 專案改名時要同步改：
  - 工作資料夾
  - `{{CODEX_CONFIG}}` 信任路徑或 MCP 路徑
  - 專案 `AGENTS.md`
  - Obsidian 專案庫資料夾
  - Obsidian 駕駛艙內文
  - Firebase MCP project directory
  - Netlify site name / site ID / output folder 記錄
- GitHub 若沒有 remote，就不需要改 repo。
- Firebase Project ID 不會因本地專案改名而改變。
- Netlify Site ID 不會因本地專案改名而自動改變。

# Project Init Sync

Use this workflow for every new project unless the user explicitly says not to.

## Default Paths

- Main Obsidian vault: `OBSIDIAN_VAULT`; for this user, `{{OBSIDIAN_VAULT}}`
- Default work root: `WORK_ROOT`; for this user, `{{WORK_ROOT}}`
- Project cockpit root: `專案庫` inside the Obsidian vault
- Project cockpit note: `專案庫/<project-name>/專案工作流程.md` inside the Obsidian vault
- Optional personal assistant global layer: `ASSISTANT_ROOT`; for this user, `{{SYNC_ROOT}}`
- Optional personal assistant global entry skill: `ASSISTANT_ROOT/skills/arry-assistant/SKILL.md`; for this user, `{{SYNC_ROOT}}/skills/arry-assistant/SKILL.md`
- Required custom-skill creation workflow: `ASSISTANT_ROOT/skills/codex-skill-creator/SKILL.md`; for this user, `{{SYNC_ROOT}}/skills/codex-skill-creator/SKILL.md`
- Optional personal assistant setup document: ask the user for the path if no local setup document exists
- Global assistant skills: `ASSISTANT_ROOT/skills`
- Project-local assistant folders: `100_Todo/`, `200_Reference/`, and optional `000_Agent/skills/`, `000_Agent/memories/`
- Standard task folders: `100_Todo/drafts/`, `100_Todo/projects/`, `100_Todo/archive/`
- Standard reference folders: `200_Reference/writing-samples/`, `200_Reference/templates/`, `200_Reference/past-work/`
- Optional reference folders: `200_Reference/docs/` for deployable/static documents and `200_Reference/scripts/` for project scripts plus versionable runtime material such as `requirements.txt`.
- Keep Python/tool virtual environments out of the project tree entirely. Create them on the machine with the shared `cross-device-sync/scripts/project-venv.sh ensure`, which resolves to `~/.local/share/agent-tools/project-runtimes/<project>/.venv`. A venv pins absolute interpreter paths and holds thousands of small files, so a synced project folder (Google Drive, iCloud, Dropbox) evicts its contents and every later import re-downloads the tree file by file. Only `requirements.txt` belongs in the repository.

When adapting this skill for another user, replace `OBSIDIAN_VAULT`, `WORK_ROOT`, `ASSISTANT_ROOT`, and `ASSISTANT_NAME` before creating files. If the user does not want a personal assistant layer, skip assistant-specific folders and sections.

## Workflow

1. Inspect the current folder first. Report what already exists and what is missing.
2. Confirm missing facts before creating files:
   - project name
   - purpose
   - work folder
   - GitHub repo needed or not
   - public or private repo
   - GitHub Pages needed or not
   - Obsidian cockpit path
   - Firebase needed or not
   - Netlify needed or not
   - deployment target
   - Agent execution notes for any known connector, MCP, sandbox, model, or script differences; the default profile is always shared Codex + Claude + AntiGravity
3. For existing projects, only fill gaps. Do not overwrite existing `AGENTS.md`, `README.md`, `.gitignore`, Firebase config, or Git history.
4. Create or update the project root `AGENTS.md` with:
   - project name, purpose, work directory
   - GitHub repo or `未建立`
   - default branch
   - Obsidian vault absolute path
   - cockpit note vault-relative path
   - GitHub Pages status or `未啟用`
   - Firebase project id or `未使用`
   - Netlify site/team/deploy status or `未使用`
   - startup/shutdown/new-project rules
   - startup runs the shared `cross-device-sync/scripts/session-sync-checkpoint.sh --phase startup --sync-root <SYNC_ROOT> --update`; shutdown runs the same script with `--phase shutdown`
   - optional personal assistant integration: always bring in the shared global personal-assistant entry skill when the user uses Arry Assistant, plus the shared core layer, project-local `100_Todo/`, `200_Reference/`, and local `000_Agent/skills` when project-only skills are needed
   - if documenting Arry Assistant Obsidian sync, state that `knowledge/` sync excludes top-level `visual-note-references/` and `.DS_Store`, while `memories/` syncs only first-level files from the root and never memory subdirectories; visual-note works use the dedicated global Knowledge plus Obsidian portfolio route
   - safety rules: no secrets, no personal or sensitive data
   Treat project `AGENTS.md` as the canonical cross-agent project rule file. Always create a thin project-root `CLAUDE.md` containing `@AGENTS.md`; do not duplicate the rules in two files. Keep AntiGravity on the same `AGENTS.md` contract.
   When an execution step differs, add one note with `Shared steps`, `Codex adapter`, `Claude adapter`, `AntiGravity adapter`, and `Verification`. A missing native feature must route through the shared script/CLI, the agent's MCP/plugin, an approved API, or a browser/manual step.
5. Create or preserve a project-root `HANDOFF.md` with only:
   - current state
   - next action
   - blockers
   - last verified date and environment
   Keep it concise, exclude secrets and personal data, and never overwrite uncommitted human notes.
   `startup-sync` must read it; `shutdown-sync` must create it when missing and update it every session. Do not make the user restate this requirement.
6. Create or fill `README.md`, `.gitignore`, and Git repo if missing.
7. Create the project-local data layer if missing:
   - `100_Todo/drafts/`
   - `100_Todo/projects/`
   - `100_Todo/archive/`
   - `200_Reference/writing-samples/`
   - `200_Reference/past-work/`
   - `200_Reference/templates/`
   - `200_Reference/docs/` when the project has deployable/static documents, local entry pages, or public-facing build artifacts
   - `200_Reference/scripts/` when the project needs scripts, automation helpers, or runtime material
   - `200_Reference/scripts/runtime/` only for regenerable script runtime such as intermediate parts and caches; never a virtual environment. The venv lives outside the project at `~/.local/share/agent-tools/project-runtimes/<project>/.venv` (see `project-venv.sh`), and `.gitignore` still excludes `.venv/` so a stray one is never committed
   - `000_Agent/skills/` only when the project needs project-specific assistant skills or local workflows
   - `000_Agent/memories/` only when the project needs project-specific assistant memory separate from the global Arry core
   - **Knowledge Template Deploy**: Copy the 8 global strategy markdown files (e.g. `context-management-strategy.md`, `verification-checklist.md`, `subagent-strategy.md`, `parallelization-strategy.md`, `advanced-memory-learning.md`, `prompt-defense-baseline.md`, `security-review-checklist.md`, `coding-standards.md`, from `ASSISTANT_ROOT/knowledge/`) into the new project's `200_Reference/templates/` folder to bootstrap the new project with the default strategy.
   - **Bootstrap Project Verification Script**: For development projects, automatically draft `200_Reference/scripts/verify_project.sh` (or `verify.py`) containing basic build/lint placeholders, guiding the project to follow `verification-checklist.md` from day one. Do not place project scripts in the project root.
8. Create the Obsidian cockpit note at `專案庫/<project-name>/專案工作流程.md` in the vault, not inside the project repo.
   - Include a deployment status block that records GitHub Pages, Firebase, Netlify, and the overall deployment target. Keep Netlify listed directly below Firebase.
   - If a personal assistant layer is used, include a short assistant integration section stating the model: shared global assistant core, project-local task/reference folders, and Obsidian as the knowledge/cockpit layer.
